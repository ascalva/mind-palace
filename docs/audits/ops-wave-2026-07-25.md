# Ops wave audit — 2026-07-25

The first independent audit at reviewer tier (delegate-skill D2). Six auditors, one
per plan plus one for the seams, each in its own worktree, each given the plan and the
diff and **not** the builder's journal. Every auditor was given the same adversarial
question verbatim: *find a way the acceptance test passes while the objective fails.*

## Verdicts

| slice | artifact | record | headline |
|---|---|---|---|
| bp-100 | CONCERNS | disclosed-partial | instrument bypassable at the slice; closed at HEAD by bp-103 |
| bp-101 | CONCERNS | accurate | 7/7 mutations fired; one falsifier proves a weaker proposition than stated |
| bp-102 | CONCERNS | overstated | the wedge detector cannot detect the wedge it was built for |
| bp-103 | **CLEAN** | **OVERSTATED** | code is right; the seal overstates *why* it is right |
| bp-104 | CONCERNS | accurate | two prose claims outrun their mechanism; surfaced two real code defects |

Five of six slices are mutation-verified as genuinely built. **No slice was theatre.**
The defects cluster in three places, and none of them is inside a plan.

## The three findings that matter

### 1. The wave's only integration point is untested (SEAMS, high)

`be225fd` wires `sweep_orphans` into supervisor start. It belongs to no plan — it was
written by the orchestrator after bp-102 had already sealed. Mutating it:

| mutation of `ops/lifecycle/launcher.py:538` | result |
|---|---|
| baseline | 85 passed |
| **delete the sweep call entirely** | **85 passed** |
| wrong run id (`sweep_orphans(0)`) | 53 passed |
| move to after `_serve()` | 44 passed |

`_FakeQueue.swept_for` is assigned at `tests/integration/test_lifecycle.py:141` and
**read nowhere in the repository**. `be225fd`'s own commit message promised the fake
recorded the run id "so a test can assert adoption and not merely the call." That test
was never written. `Launcher.start()` is never exercised against a real `JobQueue`
anywhere in the suite.

bp-101 is green because the method works. bp-102 is green because the launcher works.
Nothing tests the line that joins them, and that line is in no plan's `write_scope`.

### 2. `start --force` sweeps a live run's in-flight jobs (bp-101 + SEAMS, high)

**Two auditors reproduced this independently, from disjoint diffs, with journals
withheld.** That convergence is the strongest evidence this audit produced.

```
run A (id 10, LIVE) claimed: [(1,vault_sync,running,10), (2,research,running,10)]
run B sweeps with id 11 -> OrphanSweep(requeued=(1,), failed=(2,))
  job 1: state=queued, claimed_by_run=None   <- run A still executing it
  job 2: state=failed, error='orphaned by unclean exit of run #10'
```

`scheduler/queue.py:360-362` argues that a fresh run's autoincrement id exceeds any
stamped id, so no pre-existing row can be mistaken for this run's work. True — and it
establishes only that the sweep will not eat *its own* rows. It silently equates
"stamped by a different run" with "stamped by a **dead** run".

Nothing enforces the missing premise. `Launcher.start()` reads `last_was_clean()` — a
*ledger* predicate — and never probes `_pid_alive(prev.pid)`. `reset()` performs
exactly that probe at `launcher.py:1128` ("refusing reset — run #N is live"). **An
asymmetric guard within one file is a high-yield audit signal**: someone already
identified the hazard and the new call site did not inherit the lesson.

Reachability is the *documented* path: `launcher.py:528-529` prints "recovery mode …
then `start --force` to resume normally". Before `be225fd` a second instance was a
contention bug; after it, a second instance rewrites the first one's rows.

### 3. The wedge detector cannot detect the wedge (bp-102, high)

Plan §0: *"Without a throughput and rate readout there is no way to tell a healthy
backfill from tonight's wedged one."* Both states were built and rendered:

```
HEALTHY (genuinely embedding, daemon ALIVE)   WEDGED (the incident, daemon ALIVE)
  ZERO DRAIN (0 completed)                      ZERO DRAIN (0 completed)
  nothing completed                             nothing completed
  running while NOTHING completed this window   running while NOTHING completed this window
```

Identical. `stalled` and `wedged` both key on `done_in_window == 0`, a job-*boundary*
count; the failure mode is intra-job. `code_backfill_handler` makes one synchronous
non-checkpointing call over 423,855 ledger rows, so a *healthy* multi-hour backfill
emits zero terminal transitions and trips every flag continuously — for hours.

The false-alarm guard cannot catch it: its "healthy" fixture has `depth == 0` and no
running row, so both predicates are unreachable by construction. Mutating `stalled` to
a permanent alarm passes all 9 tests.

Plan §10 made this disqualifying on its own terms: *"The false-alarm falsifier fires →
STOP; an instrument that cries wolf will be ignored during the next incident."* It
fires. The fix is cheap and half-built: `store.vector_rows` is already read and printed
as a **level**; differencing it across two samples is the discriminator.

## Two cross-cutting defect classes

### A. The falsifier↔test gap — three slices, found independently

The plan names proposition *P*; the test proves a strictly weaker *P′*; the gap is
invisible unless you quote the falsifier verbatim and ask what the test actually proves.

| slice | plan said | test proves |
|---|---|---|
| bp-101 | "the sweep reclaims a job a **live worker** is running" | "a run does not steal **its own** work" |
| bp-100 | §6: "any new implementation must handle id collision **explicitly**" | the easy case — distinct ids |
| bp-102 | "a healthy system raises no flags" | a fixture where no flag *can* fire |

All three auditors independently proposed the same remedy for the standing brief:
**quote the falsifier verbatim in the ledger row, then state in one line what
proposition the test actually proves.** The divergence becomes mechanical once written.

### B. Instrument blindness — three slices, same shape

An instrument that does not watch the route the fix uses reports a beautiful zero
measuring nothing.

- **bp-100** — `_instrument` hooks only `VectorStore._table()`. A mutant that keeps a
  byte-identical O(N) scan but reaches the table via `self._db.open_table(TABLE)` turns
  both ratchets **green with the defect intact**. What saved bp-100 was the strict-xfail
  markers XPASSing — an *accidental* net. bp-103 closed it properly; verified at HEAD.
- **bp-102** — the wedge detector above.
- **bp-103** — the cost ratchet counts `to_pylist()` and `scan()/search()`, but the
  shipped fix uses `count_rows(where)` + `update(where, values)`, which fall through
  `_CountingTable.__getattr__` **uncounted**. The green is satisfied by any
  implementation avoiding the old routes — including one that does nothing. What closes
  it is an assertion in a *helper* (`_cost_of_supersede`), not the ratchet, and the plan
  never named that as the guard.

The generalized auditor move, in operational form: *enumerate the routes the meter
watches; enumerate the routes the fix uses; if the intersection is empty, the green
measures absence, not correctness.*

## Record-vs-artifact defects

bp-103's auditor proposed a second verdict axis, and the wave vindicates it: three of
its eight findings are defects in the **narrative** with a correct artifact underneath.

- **bp-103** — the seal's headline claim ("removing the xfail markers against a blind
  instrument would have measured the METER") is **not supported**. Reverting the meter
  to bp-100's blind version leaves both ex-xfail ratchets green against the shipped
  code; only two bp-103-authored tests fail. The instrument widening is valuable as
  *prophylaxis*, not as a rescue. The forward claim ("the ratchets are strictly
  stronger") *is* true, mutation-confirmed.
- **bp-102** — every citation to its own two findings points at the **wrong document**
  (10 sites). The seal renumbered `0175→0178`/`0176→0179` in the finding files but not
  in source. Both wrong ids resolve to *real, unrelated* findings, so a reader is
  misled rather than 404'd.
- **bp-104** — two Chapter 2 claims outrun their mechanism: the ring end-state asserted
  as present fact (`core/** ∖ core/kernel/**` ≠ `core/** ∖ INNER`; 6 modules
  mis-located), and "the runtime guard and the kernel anchor hold the property
  **unconditionally**" when the anchor is inert and the guard disclaims its own
  completeness. The chapter retracts both in §residuals — the word is unqualified where
  it is *used*.

Given the standing `completion-claims-honesty` rule, an overstated seal is a
first-class defect, and the CLEAN/CONCERNS/SERIOUS scale cannot express it. **Adopt the
two-axis verdict: `artifact: clean|concerns|serious` × `record: accurate|overstated|misleading`.**

## Safety-discharge findings (non-negotiable #1)

Surfaced by bp-104's auditor, and *not* bp-104's fault — bp-104 is the artifact that
made them visible, and its `finding-0185` got there first.

1. **The outer self-containment ratchet regressed 19 → 20 and nothing detected it.**
   Counts: `97c245c`=19, `bdcd9bc`=19, `a806daa`=20, `ff36348`=20. Added by `4acb9f0`
   (bp-092): `core/ingest/code_corpus.py:56 → ops.code_snapshot`. The test asserts only
   `violations == []`; the monotonicity rule lives **inside an f-string in the failure
   banner**. *A red-by-design ratchet is structurally blind to its own regression* —
   every future core→sibling import is free. One-line fix: pin `len(violations) <= 20`.
2. **`hvac` is reachable from core in two hops the direct-only lint cannot see.**
   `core/factory/factory.py:182 → config.secrets_backend → hvac.Client(url=...)`.
   `hvac` is *in* `NETWORK_MODULES` with the comment "never core". What actually stands
   between a `[secrets]`-enabled core process and off-host egress: `hvac` is an
   uninstalled optional extra (a packaging accident), and `core/sealing.py`'s socket
   monkeypatch (which disclaims native-extension bypass). The `pf` anchor is **inert** —
   committed but owner-loaded, `verify_planes.py` reports `PENDING`.

## The systemic finding: `write_scope` is not a partition of the diff

The wave's five scopes covered every file **except the two that mattered**. Both
serious findings live in the ~35 ungoverned lines.

`be225fd` exists *because the workflow worked correctly*: bp-101 hit its write_scope
boundary, refused to route around it, and filed `finding-0177` with the exact patch —
textbook. The failure is what happened next: **a finding whose resolution is a code
change was discharged by an orchestrator commit instead of re-entering the artifact
chain.** The chain says findings return through the same gate brainstorms do.

Proposed mechanism, detectable by arithmetic rather than judgement:

> Diff `wave_base..HEAD`; subtract every plan's `write_scope`, `docs/findings/**`, and
> the orchestrator's declared files. **Any `*.py` in the remainder blocks the seal**
> until brought under a plan or explicitly waived on the record.

Under that gate this wave stops on `tests/integration/test_lifecycle.py` and the
`launcher.py` hunk — both serious findings, caught mechanically. `scope-guard` already
knows every plan's scope; this reads the same data at *wave* level instead of session
level. It is the missing pre-hoc counterpart to the `journal-gate` diff audit.

The preferred workflow fix: **the integrator plan.** A wave that generates hand-off
findings mints one final `bp-N` whose `write_scope` is the seam files and whose §7
carries an acceptance criterion and named falsifier for each hand-off. Blessed like any
plan, audited like any plan. bp-101→bp-102's hand-off was known at graduation.

Minimum viable alternative: hand-offs are absorbed by the *receiving* plan before it
seals. `finding-0177` should have been a bp-102 §7 item.

The rule that generalizes: **the last commit before a seal must never be the first
commit of a behaviour.** If integration reveals work, that work opens a plan; it does
not close a wave.

## What the audit design proved

All five deliberate design choices earned their keep:

1. **The orchestrator did not audit.** It authored all five plans; four of its premises
   were falsified by builders. Its re-read would have re-projected its own intent.
2. **Withholding the journals was decisive.** bp-101's auditor: *"F1 is precisely the
   thing a builder's own journal would have argued me out of — the builder's reasoning
   is internally airtight and only fails on an assumption stated nowhere in the diff."*
3. **Worktrees enabled mutation checks**, which separated real ratchets from theatre in
   every slice and produced every high-severity finding.
4. **Central filing avoided id collisions** (three already occurred this session).
5. **No full-suite runs** — targeted tests plus mutation only; no ollama contention.

**The single strongest signal: bp-101 and SEAMS converged on the same defect from
disjoint diffs with journals withheld.** Independent convergence is evidence a single
reviewer cannot produce.

## Lessons for the standing `auditor-<domain>.md` briefs

The gap that made this run necessary: `.claude/agents/` holds only `builder.md` and
`scribe.md`. The owner's 2026-07-23 ruling could not be executed as written for the
second time. This run is that ruling's input.

**Converged structure** (all six auditors proposed variants of the same shape):

```
1. Environment      — exact incantation in a fresh worktree; PYTHONPATH; known footguns
2. Domain contract  — subsystem invariants, and which are ENFORCED vs conventional
3. Production probes— live artifacts to read-only-query, with the queries
4. Known hazards    — pre-existing defects, so regressions are reported separately
5. Ritual           — quote falsifier verbatim → name test → state what it ACTUALLY
                      proves → mutate the specific guard → revert
6. Taxonomy         — the authoritative ftype set and routing table
7. Prohibitions     — no journal, no findings/ writes, no full suite
8. Dismissal list   — hypotheses already disproven, so they are not re-run
```

**Environment facts that cost every auditor a round trip** (put these in §1):
- `uv run --extra dev pytest` — bare `uv run pytest` fails in a fresh worktree
- `uv sync --extra dev` is a required first step in a new worktree
- `PYTHONPATH=.` for ad-hoc probe scripts (package is not installed editable)
- `timeout(1)` does not exist on this macOS shell
- `pytest tests/unit` (subdirectory path) **mis-collects** — 36 errors; collect from repo root
- `cwd` resets between Bash calls in agent threads — absolute paths only
- `latexmk` needs `PATH=$PATH:/Library/TeX/texbin`; `docs/book/main.pdf` is gitignored
- artifact ids resolve by frontmatter `id:`, **not** by filename

**Mutation catalogue by defect class** (the highest-yield converged proposal):
revert-the-fix · **blind-the-instrument** · break-the-escaping · delete-the-bound
(`limit`/`k`/timeout) · no-op-the-operation. Each with its expected failure signature.
Explicitly: **if a mutation changes nothing, the falsifier is inert — that is a
finding, not a pass.**

**Named procedures worth promoting:**
- **The tense test** (bp-104) — for every present-tense architectural assertion, open
  the cited §: *is it describing state or intent?* Migration plans, end-states, and
  M-gates are the reservoir. Both of bp-104's real defects came from this generator.
- **The closure reflex** (bp-104) — when an invariant is phrased "no path exists" but
  the checker is per-file, build the graph. ~40 lines of AST walking found the `hvac`
  chain in one run.
- **The three-ref ratchet sweep** (bp-104) — recompute any ratchet's metric at the
  previous edition ref, the plan's base, and HEAD; then grep whether monotonicity is
  *asserted* or merely *narrated*. This turned "the ratchet is red" into "the ratchet
  regressed and nothing noticed".
- **Build both states** (bp-102) — for any meter or gauge, construct the complementary
  state and diff the output. If the outputs match, the instrument has failed regardless
  of test results.
- **The read-only-verification recipe** (bp-102) — bare temp data dir → snapshot
  filenames → run the command → diff. Ten lines; proved `status` is not read-only.
- **The citation sweep** (bp-102) — resolve every `finding-\d+`/`bp-\d+`/`dn-*`
  reference in shipped source to its actual title. One loop caught 10 wrong citations.
- **Enumerate every constructor of the changed class** (bp-101) — new in-object state
  is only safe if *every* construction site sets it. Six kept the `None` default.
- **A widened Protocol is a coverage regression until proven otherwise** (SEAMS) — the
  new method's only test implementation is a fake *by construction*. Mechanical check:
  grep the fake's recording attribute; **written and never read ⇒ decorative seam.**

**Auditor's structural edge, worth naming explicitly:** the auditor is often outside
the `write_scope` that stopped the builder. bp-103's auditor closed `finding-0180`'s
open reachability question with one read-only probe the builder was structurally unable
to run. Standing permission: schema and count reads yes; `add`/`update`/`delete`/`drop`
never.
